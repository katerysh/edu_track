Трек «Вайбкодинг» — структура

1. Сквозная идея трека

Тезис из идей Как звучит в программе
Инструмент ломает прежнюю логику работы с ИИ Не «спросил чат — получил ответ», а среда, где ИИ работает внутри проекта
Мы задаём рамки и ведём сотрудника в них Участник учится ограничивать и направлять агента, а не «угадывать промпт»
agents.md — должностная инструкция для ИИ-агента Центральный артефакт трека: правила роли, границ, стиля, контекста
Переосмысление роли ИИ: мы управляем вниманием Фокус трека: что агент видит, что игнорирует, что накапливает
Цель трека
Участник умеет организовать рабочее пространство так, чтобы ИИ-агент стабильно помогал в его функции, а не «отвечал в вакууме».
Не цель
Сделать из всех разработчиков; глубокий разбор моделей; замена корпоративных политик ИБ.

Рабочий стек (из идей): VS Code + Василиса (уточнить финально).

3. Блок «До трека» (вход и преридеры)

3.1. Мотивационная анкета — порог входа

Зачем: отсеять случайных слушателей, понять функции и готовность, собрать материал для персонализации Практикума 1.

Черновик блоков анкеты:

  1. Мотивация: зачем идёт на трек, какую задачу хочет решить.
  2. Функция / роль: чем занимается день за днём.
  3. Опыт с ИИ: чат / код / документы / «почти не пользовался».
  4. Техготовность: Linux, возможность установить VS Code + Василису.
  5. Ожидания: что считает успехом через 2–3 недели после трека.

3.2. Установка инструмента — после отбора

После прохождения отбора на трек участник получает полную инструкцию по установке и чек-лист «готово / не готово».
Синхронное время не тратить на установку с нуля (только troubleshooting на вводной встрече).

3.3. Преридеры (асинхронно)

Вынести из живых встреч (после вводной встречи):

  • коротко: чем агент в IDE отличается от чата;
  • зачем нужны рамки и файлы инструкций;
  • глоссарий: проект, контекст, агент, AGENTS.md / agents.md.

4. Вводная встреча

Зачем Подготовить почву под персонализацию и снять технический барьер
Содержание 1) Проверить установку ПО / помочь с troubleshooting. 2) Прописать свою функцию (роль, типовые задачи, артефакты, ограничения)
Результат Короткий профиль «я как сотрудник» + подтверждение, что среда запускается
Связь с треком Входной материал для Практикума 1 (документ под профиль) и Практикума 2 (agents.md под реальную роль)

5. Каркас практикумов

Практикум 1 Философия использования и «зачем мне это»

Фокус Смена модели мышления: от чата к управлению вниманием агента
Практика Участник сам создаёт документ: что такое вайбкодинг-среда и как она помогает исходя из его профиля
Формат артефакта HTML, стилистика шаблона РТК
Образовательный результат Объясняет своими словами ценность инструмента для своей функции; формулирует философию использования на 5–7 тезисов
Итог Концептуализация + начало эксперимента (документ о себе)

Практикум 2 Архитектура папки и agents.md

Фокус Организация контекста проекта: что хранится, что накапливается, какие правила обязан учесть ассистент
Практика Спроектировать структуру папки под свою/учебную задачу; написать agents.md как должностную инструкцию агента
Ключевые вопросы Что агент должен видеть всегда? Что не должен трогать? Что растёт со временем (логи, черновики, правила)?
Образовательный результат Есть рабочая схема папки + первый осмысленный agents.md
Итог Конкретный опыт + экспериментирование

Практикум 3 Создание решений руками

Фокус Применение среды: файлы, итерации, мини-продукты
Практика (из идей) Старт со «Змейки» → другие игры / мини-решения → работа с файлами → парсинг сайта (по уровню группы)
Смысл блока Не «научиться писать змейку», а прожить цикл: задача → контекст → агент → правки → результат в файлах
Образовательный результат Минимум один завершённый артефакт + понимание, как повторить цикл на рабочей задаче
Итог Конкретный опыт + рефлексия переноса

6. Сквозные артефакты участника

К концу трека у человека в папке должно лежать:

  1. Профиль функции (вводная встреча).
  2. HTML-документ «инструмент × моя роль» (Практикум 1).
  3. Архитектура папки + agents.md (Практикум 2).
  4. Мини-решение (игра / парсер / рабочий прототип) (Практикум 3).
  5. (Рекомендуется) План переноса: одна рабочая задача на ближайшую неделю.

7. Черновик образовательных результатов всего трека

К концу трека участник сможет:

  1. Объяснить, чем работа с ИИ-агентом в IDE отличается от чата и почему важны рамки внимания.
  2. Описать ценность подхода применительно к своей функции.
  3. Спроектировать структуру папки проекта под накопление контекста.
  4. Написать agents.md как должностную инструкцию агента.
  5. Пройти цикл постановки задачи → работа агента с файлами → итерация → готовый мини-результат.
  6. Сформулировать одну задачу для переноса в свою работу.

8. Следующие шаги по сборке трека

  1. Сходить к коллегам из ШП, зафиксировать опыт (что сработало / что ломалось).
  2. Утвердить инструмент: VS Code + Василиса (и терминологию в материалах).
  3. Написать инструкцию установки + чек-лист к вводной встрече.
  4. Собрать мотивационную анкету и критерии допуска.
  5. Набросать преридеры (коротко, 15–30 мин чтения).
  6. Детализировать планы Практикумов 1–3 по шаблону образовательного события (тайминг, роли, инструменты: Толк / Гранатум / LMS).
  7. Подготовить шаблон HTML РТК и эталонный agents.md для демо.
